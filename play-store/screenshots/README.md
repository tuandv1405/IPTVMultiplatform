# Store screenshots

Captured from a running Android emulator on 2026-09-16 (API 37).

**No third-party content appears in any of these images** — not broadcast
content, and not affiliate imagery either.

Channels are generated by `make-demo-assets.py`: invented names (TS One, TS
News, TS Sport …), original logos, and video frames drawn in the app's own
palette and stamped "SAMPLE CONTENT — NOT A BROADCAST". A listing built on a
real playlist would publish someone else's broadcast frames, station logos and
channel marks, which is what attracts an IP complaint on an IPTV listing.

The affiliate offers are handled by screen choice rather than by data. They come
from Remote Config (`ads_url`) independently of the playlist, so no demo data
removes them; instead every screen here is one where no offer is rendered:

- the offer is inserted at index 0 of a channel list, so the channel shots are
  scrolled past it;
- the player screen always carries one under the title, so the player shot is
  the **landscape fullscreen** view, which has none;
- Home above the channel list, the import form and Profile never show one.

| --- | --- | --- | --- |
| `phone/` | 1080×1920 (player 1920×1080) | 9:16 / 16:9 | 5 |

There is no ad-free Home shot at tablet width: the screen is tall enough that
the offer below the group chips is always on screen, so the tablet sets start at
the channel list. Tablet screenshots are optional for Play, and two qualify.

All pass Play's constraints: every side within 320–3840 px, and no side more
than twice the other. **The emulator's native 1080×2424 is 2.24:1 and would be
rejected**, which is why the captures override the display size.

## Building the demo playlist

```bash
python play-store/screenshots/make-demo-assets.py
python -m http.server 8099 --bind 0.0.0.0   --directory play-store/screenshots/demo-server
```

Then in the emulator, add an IPTV source pointing at
`http://10.0.2.2:8099/demo.m3u`. The generated `demo-server/` directory is about
250 MB of HLS segments and is gitignored; rebuild it whenever you need it.

Note the emulator keyboard capitalises after `/`, so the URL may arrive as
`Demo.m3u`. On Windows that still resolves; on a case-sensitive host, retype the
last segment.

## Regenerating

With an emulator running and the app installed:

```bash
ADB="$ANDROID_HOME/platform-tools/adb"

# 1. Play-compliant display size (the native one is too tall)
$ADB shell wm size 1080x1920 && $ADB shell wm density 420

# 2. Clean status bar: fixed clock, full battery, no notification icons
$ADB shell settings put global sysui_demo_allowed 1
$ADB shell am broadcast -a com.android.systemui.demo -e command enter
$ADB shell am broadcast -a com.android.systemui.demo -e command clock -e hhmm 0930
$ADB shell am broadcast -a com.android.systemui.demo -e command battery -e level 100 -e plugged false
$ADB shell am broadcast -a com.android.systemui.demo -e command notifications -e visible false

# 3. Capture
$ADB exec-out screencap -p > phone/01-home.png

# 4. Restore
$ADB shell am broadcast -a com.android.systemui.demo -e command exit
$ADB shell wm size reset && $ADB shell wm density reset
```

Tablet sizes: `wm size 1200x1920 && wm density 240` (7"),
`wm size 1600x2560 && wm density 320` (10"). Force-stop and relaunch the app
after changing size so Compose re-measures from scratch.

## Before uploading

- Upload in the listed order; the first screenshot is what most people see.
- `phone/03-player.png` is the only landscape image. Play accepts mixed
  orientations; if you would rather the set read as one orientation, drop it —
  but it is the only player shot without an affiliate offer in it.
- Do not swap in a real playlist "to look more convincing". Accurate screenshots
  are a Play requirement, and the app genuinely ships with no channels.
- If the offers are ever moved below the fold in the app, recapture: the
  portrait player and the tablet Home screen both become usable again.
