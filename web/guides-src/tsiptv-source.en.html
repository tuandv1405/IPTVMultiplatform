TS IPTV Source format

A TS IPTV Source is one JSON file that describes a complete, branded collection: who made it, its colours, its home screen layout, live TV and radio channels, movies, series with seasons and episodes, programme guides, and links to other playlists, guides and addons. It is open, documented on this page, and checked by a published JSON Schema.

TS IPTV includes no channels and no sources. A TS IPTV Source contains only the links its creator puts in it; TS IPTV does not list, host or recommend any. Every example on this page uses example.com placeholders, a public test stream, public-domain films from archive.org, or TS IPTV's own example files on tsiptv-8bdd6.web.app.

Files: JSON Schema (https://tsiptv-8bdd6.web.app/schema/tsiptv-source-v1.json, draft 2020-12) · examples minimal-live, vod-catalog, composed-includes · browser validator.

What it is

M3U describes a list of channels. A TS IPTV Source describes a whole collection, and how its home screen should look. Use it when you want movies and series with posters and episodes, your own sections and colours, several streams per item, or when you want to combine existing M3U playlists, XMLTV guides, Stremio-compatible addons and other sources into one.

The format follows five rules:

  1. Data, never code. No scripts, expressions, HTML or Markdown. Every text is plain text; TS IPTV never runs anything from a source.
  2. Links, not content. The file carries the links its creator supplies. The format, the schema and the app ship no content.
  3. Easy by hand. The smallest valid file is ten lines. Shorthands cover the common cases (url instead of streams, a plain string instead of a translated object).
  4. Forward compatible. Unknown fields are ignored and unknown values fall back in a defined way, so an older app keeps reading newer files. Only a breaking change raises version.
  5. Same meaning as M3U. Headers, DRM and catch-up mean exactly what they mean in Kodi-style M3U, so a channel plays the same in both formats.

This page is the public reference of version 1. The JSON Schema is stricter than the app, so a file that passes it is almost always accepted. The exceptions are things the schema cannot see: a file larger than 5 MiB; format placed after the first 64 KiB; impossible calendar dates such as 2026-02-30 (TS IPTV warns and ignores the field); duplicate ids and references to missing items (checked by the app and by the validator); and includes that fail or form a cycle (E_INCLUDE, E_INCLUDE_CYCLE, and E_EMPTY if nothing else is left).

Quick start

The smallest useful file: one channel that really plays (the Mux public test stream, Big Buck Bunny © Blender Foundation, CC BY 3.0).

{
  "$schema": "https://tsiptv-8bdd6.web.app/schema/tsiptv-source-v1.json",
  "format": "tsiptv-source",
  "version": 1,
  "id": "com.example.my-channels",
  "meta": { "name": "My Channels" },
  "channels": [
    { "id": "test-hls", "name": "HLS Test Channel", "url": "https://test-streams.mux.dev/x36xhzz/x36xhzz.m3u8" }
  ]
}

Save it as my-channels.tsiptv.json (UTF-8), put it on any HTTPS host, and add the link in TS IPTV. The $schema line makes editors such as VS Code check the file and suggest fields as you type.

General rules

  • x- members: any field whose name starts with x- is yours (notes, tool data). TS IPTV ignores it and the format will never define one. This does not apply to header names, language keys or DRM key ids, which are data.
  • null is the same as leaving the field out.
  • Unknown fields are ignored by the app, but the schema reports them so you catch typos.
  • Text is trimmed; a value that is empty after trimming is invalid. Lengths count characters (Unicode code points).
  • Control characters: the schema allows none in texts, except line breaks in long texts (descriptions). TS IPTV is lenient here: a line break or control character in a one-line text is replaced by a space and reported as a warning, not an error. URLs and catch-up sources must contain none; header values allow only tab.

Texts and translations

Every visible text is either a plain string, in the language of meta.language, or an object that maps language tags to strings:

"name": "Movies"
"name": { "en": "Movies", "vi": "Phim lẻ", "zh-CN": "电影" }
  • Text (names, titles): 1–200 characters, one line. Long text (descriptions): 1–5,000 characters; line breaks allowed (LF, CR or CRLF).
  • Language tags: en, vi, zh-CN, pt-BR (pattern ^[a-z]{2,3}(-[A-Za-z0-9]{2,8})*$); at most 30 per object.
  • TS IPTV picks, in order: the app's language exactly (zh-CN), then its main language (zh, then any zh-…), then meta.language, then en, then the first entry.
  • Texts are shown as written: no HTML, no Markdown.

Ids, URLs, headers, colours

TypeRule
Id^[A-Za-z0-9][A-Za-z0-9._-]{0,127}$: letters, digits, ., _, -, case-sensitive, no : (the colon is reserved for included items, includeId:itemId). Every id of a channel, movie, series, episode and include must be unique in the file. The first one wins, in this order: channels, movies, series (each followed by its episodes), includes; an item that is dropped does not claim its id.
URLAbsolute http:// or https://, at most 2,048 characters, no spaces or control characters. Every URL in the file (streams, images, includes, licence servers) follows this rule; rtmp:, udp:, file:, data: and all other schemes are invalid. Prefer https.
HeadersAn object of header name → value, for example { "User-Agent": "Mozilla/5.0", "Referer": "https://example.com/" }. At most 20. Values are sent exactly as written (not URL-decoded), up to 4,096 characters. Host, Content-Length, Connection and Transfer-Encoding are forbidden. Headers go with every request of the stream (manifests, segments, keys), not with the DRM licence request and not with subtitle files.
Colour#RRGGBB.

accentapp accentFocus rings, selected chips, buttons, progress bars.

Card style: style is auto, poster (2:3), landscape (16:9), square, logo (channel logo tile) or list (one line: logo, name, programme now on); auto means poster for movies and series, logo for TV, square for radio, landscape for episodes, and the item's own posterShape for items from a Stremio-compatible catalogue. corner is none, small, medium or large. showTitles hides names on cards when false (channels and lists always show them).

Legibility. TS IPTV keeps its own light text colour. If your background colour (or a gradient stop) gives a contrast below 4.5:1 with that text, TS IPTV uses its own background (a background image is kept). If the accent has a contrast below 3:1 with the background, both accents are replaced by the app's. Appearance applies to the source's home and detail pages only; the player, dialogs and settings keep the app theme.

layout: the home screen

layout.home is a list of 1–30 sections, drawn top to bottom.

"layout": {
  "home": [
    { "type": "hero", "query": { "from": "movies", "limit": 5 } },
    { "type": "row", "title": { "en": "Continue watching", "vi": "Xem tiếp" }, "query": { "from": "continueWatching" } },
    { "type": "row", "title": "News", "query": { "from": "channels", "groups": ["News"] }, "card": { "style": "logo" } },
    { "type": "grid", "title": "All channels", "query": { "from": "channels", "sort": "number" }, "groupChips": true }
  ]
}
Section fieldMeaning
type (required)hero (banner carousel, 1–10 items), row (one horizontal line, default 20 items, at most 100) or grid (all matching items, loaded in pages).
idLets TS IPTV remember the scroll and focus position of the section.
title, subtitleHeading and smaller line (not shown on a hero).
queryWhat the section shows (required, except a hero with items).
itemsHero only: hand-made banners { "image" (16:9, required), "title", "subtitle", "target", "autoplay" }. A hero has query or items, not both.
cardCard style for this section (ignored by a hero).
seeAllRow only (default true): a “See all” action opening the whole query as a grid.
groupChipsGrid of channels or radio only: group filter chips above the grid.

A hero with a query uses each item's backdrop, else poster, else logo, and skips items without an image. A banner's target is the id of a channel, movie, series or episode (included items as includeId:itemId); without a target the banner is decorative. autoplay: true starts playback of the target (channels, movies and episodes only): a channel plays at once; a movie opens its detail page and an episode opens its series' detail page, and playback starts straight away, so Back returns to that page. Banners cannot open websites. A section that finds no items is not drawn.

Queries

Query fieldMeaning
from (required)channels, radio, movies, series, catalog (a catalogue of a Stremio-compatible addon include), continueWatching, favorites.
includeOnly items from the include with this id. Required for catalog, where it names the stremio include.
catalogFor from: "catalog": { "type", "id", "genre"? } of a catalogue declared in that addon's manifest.
idsOnly these items, in this order (1–500; included items as includeId:itemId). Unknown ids are skipped.
groups, genres, tagsItems whose groups (channels), genres (movies, series) or tags contain any of these; case-insensitive.

Filters combine with AND between fields and OR inside a field. A filter that does not apply (for example genres on channels) is ignored. For catalog, only catalog.genre filters and the addon's own order is kept. continueWatching (partly watched movies and episodes, recently played channels) and favorites (favourite channels) come from the viewer's own history, never from the file; they stay hidden until they have items.

Default layout

Without layout, TS IPTV shows: Continue watching; a hero of movies (only if a movie has a backdrop); Movies; Series; Radio; and a grid of Channels sorted by number with group chips. Empty sections are left out.

Channels, movies and series

Playable fields, shared by channels, movies and episodes. An item has exactly one of url and streams:

urlOne stream. Short for "streams": [{ "url": … }].

Movie

id and name are required, plus the playable fields. Optional: originalName, poster (2:3), backdrop (16:9, used by heroes and detail pages), logo (title logo), description, year (1870–2100), releaseDate (YYYY-MM-DD), runtimeMinutes (1–1,440), genres (0–10), cast (0–50), directors (0–20), countries (ISO codes such as US), languages, ageRating (as printed, for example PG-13), tags, subtitles (0–30).

Series, seasons, episodes

{
  "id": "fleischer-superman",
  "name": "Fleischer Superman",
  "year": 1941,
  "endYear": 1943,
  "seasons": [
    {
      "number": 1,
      "episodes": [
        { "id": "fleischer-superman-s1e1", "number": 1, "name": "The Mechanical Monsters",
          "url": "https://archive.org/download/superman_the_mechanical_monsters/superman_the_mechanical_monsters_512kb.mp4" }
      ]
    }
  ]
}
  • A series has id and name (required), originalName, poster, backdrop, logo, description, year (first year), endYear (last year, not before year; absent = ongoing), genres, cast, countries, languages, ageRating, tags and seasons (1–100). It has no playable fields, and no directors, releaseDate, runtimeMinutes or subtitles.
  • A season has number (0–999, unique in the series; 0 = Specials, listed last), optional name, poster, description, and episodes (1–500).
  • An episode has id (unique in the whole file; used for watch progress), number (unique in the season), name, the playable fields, and optional description, thumbnail (16:9), releaseDate (a future date means “upcoming”, listed but not playable), runtimeMinutes, subtitles.

DRM

"drm": { "system": "widevine", "licenseUrl": "https://license.example.com/widevine", "licenseHeaders": { "X-Example": "1" } }
"drm": { "system": "clearkey", "keys": { "000102030405060708090a0b0c0d0e0f": "00112233445566778899aabbccddeeff" } }
  • system: widevine, playready (licence URL required) or clearkey (a licence URL, or keys: 1–20 pairs of 32-hex key id → 32-hex key).
  • TS IPTV sends the raw challenge to licenseUrl and expects the raw licence back; licenseHeaders go with that request only. Wrapped or JSON licence protocols are not part of version 1.
  • Widevine plays on Android; PlayReady on Android devices that support it (a PlayReady CDM, mostly TVs); ClearKey on Android for DASH only. On iPhone, iPad and desktop, a channel skips streams with DRM and plays its next stream without DRM; if there is none, TS IPTV shows “This channel is DRM-protected. DRM is not supported on this device.” For a movie or episode, a stream with DRM picked on the detail page shows that same message, so give such items a stream without DRM as well.
  • Publish only keys and licence servers you are entitled to share.

Catch-up

catchup uses the same modes and placeholders as Kodi M3U catch-up: { "mode", "source"?, "days"? (1–60, default 7), "correctionHours"? (−24 … +24) }. mode is default (source is a full URL template starting with http:// or https://), append (source is appended to the live URL, for example ?utc={utc}&lutc={lutc}), shift, flussonic, flussonic-ts or xc. For default and append, source is required and never trimmed: any space or control character makes it invalid (W_FIELD), the catch-up is dropped and the channel plays live only. The other modes build the URL from the live link and ignore source. TS IPTV stores catch-up information; playback of past programmes comes later.

Subtitles

{ "url" (WebVTT or SubRip), "language" (required), "label"?, "format"? ("vtt" or "srt") }. Subtitles start Off: the viewer turns one on under “Subtitles” in the player's “Playback options” (see streams). On Android, a subtitle without label shows the language name, and subtitle files are requested without the stream's headers, so host them where no token or Referer is needed. On desktop, subtitles load, but how they are labelled and whether headers are sent is not yet verified. iPhone and iPad do not show subtitles yet.

epg and includes

epg is a list of XMLTV guide links, each a URL string or { "url", "refreshHours"? } (1–720, default 24). Guides may be gzip-compressed. Programmes are matched to channels by epgId; a channel without epgId is matched by name (case, accents and spaces are ignored).

"includes": [
  { "id": "news", "type": "m3u", "url": "https://example.com/playlists/news.m3u", "name": "Partner news" },
  { "id": "guide", "type": "xmltv", "url": "https://example.com/epg/guide.xml.gz", "refreshHours": 12 },
  { "id": "sampler", "type": "stremio", "url": "https://addon.example.com/manifest.json" },
  { "id": "archive", "type": "tsiptv-source", "url": "https://example.com/archive.tsiptv.json" }
]

id (required)Unique Id; prefixes the included items (news:ExampleTV.us). Must not start with epg- (reserved for epg links).
type (required)m3u, xmltv, stremio or tsiptv-source.
url (required)For stremio, the manifest link ending in /manifest.json.
nameShown in “About this source” and in error messages.
refreshHoursMinimum hours between automatic fetches (1–720, default 24).
headersSent when fetching an m3u, xmltv or tsiptv-source document; not sent to addons or streams.
TypeWhat it addsItem ids

  • Depth and cycles: the root is depth 1; included sources may include others down to depth 3. An include of any type below depth 3, or one whose URL is already on the path, is refused (E_INCLUDE_CYCLE).
  • Totals per refresh: at most 20 includes in the whole tree (guide links not counted), 50 MiB fetched (all documents including the root; a 304 counts 0), and 20,000 channels, 5,000 movies and 1,000 series after merging. An M3U include may be up to 20 MiB, an XMLTV include up to 100 MiB, a TS IPTV Source include up to 5 MiB.
  • Failures: a failing include never fails your source. TS IPTV keeps the last good copy; without one, sections using that include are hidden.
  • Adult content: if any included source has meta.adult: true (or any value that is not a boolean), or any addon's manifest declares adult content, TS IPTV asks for the 18+ confirmation for the whole source before storing anything. If a later refresh makes a source you have not confirmed adult, the new content of the include that caused it is held back (the previous copy stays) until you confirm in “About this source”.

Security and privacy

  • TS IPTV never runs, evaluates or renders as markup anything from a source.
  • Only http and https links are ever opened.
  • A source cannot open websites, install anything or download files. Importing fetches only the file and its includes; images load when shown; streams load only when the viewer presses play.
  • URLs and headers may carry tokens. TS IPTV does not send them to analytics, crash reports or its own servers, and does not log them in release builds.
  • Home servers on your local network are allowed.
  • Adult content always needs the 18+ confirmation (root or includes).

Versions and unknown values

New optional fields and new values are added to version 1 over time, at the same schema URL. When TS IPTV meets a value it does not know yet, it falls back instead of failing:

Unknown value inWhat happens
section type, query fromThe section is skipped.
query sortsource order.
card style / cornerauto / medium.
channel typeTreated as tv.
include typeThe include is skipped (E_INCLUDE).
stream mimeTypeThe hint is ignored.
drm.systemThe stream is never played without DRM; it is unplayable on that device.

A change that would alter the meaning of existing files will be version 2, with a new schema (tsiptv-source-v2.json); the version 1 schema stays published.

Validation: errors and warnings

TS IPTV checks a source on three levels. Document errors reject the file. Item errors drop the item or field and import the rest. Warnings change nothing but are listed. Every problem is listed as path — CODE: explanation, for example channels[3].url — E_URL: … (the explanation is a short sentence in the app's language).

The browser validator runs the JSON Schema and the reference checks on your file before you publish it.

A source built from includes

Download composed-includes.tsiptv.json
  • No items of its own: an M3U playlist (live), an XMLTV guide (guide), the sample addon (sampler) and the vod-catalog source above (cinema).
  • The hero shows movies from cinema; “On air” lists the M3U channels as a list with the programme now on; a row shows the addon's movie catalogue; ids picks two films by their namespaced ids (cinema:big-buck-bunny); the last grid shows every channel with group chips.

Create your own, step by step

  1. Start from the minimal file. Download minimal-live.tsiptv.json and open it in VS Code (the $schema line gives you autocompletion and red underlines for mistakes). Change id to a reverse-DNS name of your own (com.example.mytv) and meta.name.
  2. Add your channels. One object each, with id, name, url, and optionally number, logo, groups, epgId and headers: 
    { "id": "news-hd", "name": "Example News HD", "number": 10, "groups": ["News"],
  "logo": "https://example.com/logos/news.png", "epgId": "ExampleNews.us",
  "url": "https://cdn.example.com/news/index.m3u8",
  "headers": { "User-Agent": "Mozilla/5.0", "Referer": "https://example.com/" } }
    Add the guide with "epg": ["https://example.com/guide.xml.gz"].
  3. Add movies and a series. Movies need id, name and url (or streams); add poster, backdrop, year, genres and description for a good detail page. A series needs seasons → episodes, each episode with its own unique id, a number, a name and a url.
  4. Add appearance and a layout. Pick an accent that stands out on a dark background, then list your sections: 
    "appearance": { "accent": "#FFB300", "card": { "style": "poster", "corner": "large" } },
"layout": { "home": [
  { "type": "hero", "query": { "from": "movies", "limit": 5 } },
  { "type": "row", "title": "News", "query": { "from": "channels", "groups": ["News"] }, "card": { "style": "logo" } },
  { "type": "row", "title": "New movies", "query": { "from": "movies", "sort": "yearDesc" } },
  { "type": "grid", "title": "All channels", "query": { "from": "channels", "sort": "number" }, "groupChips": true }
] }
  5. Translate. Replace a plain string with { "en": "…", "vi": "…" } wherever you want another language, and set meta.language to the language of your plain strings.
  6. Validate. Fix everything VS Code underlines, or paste the file into the validator. Check that every id is unique and has no :.
  7. Host it (next section), add it in TS IPTV, and read the preview: the counts, the list of servers, and any skipped items. When you publish a change later, keep the same link and id, and increase revision.

Already have an M3U playlist? You do not need to convert it: add it as an m3u include and place its channels with queries.

Host it

  • Any static HTTPS host that returns the file itself works: https://raw.githubusercontent.com/<user>/<repo>/<branch>/my.tsiptv.json, https://<user>.github.io/<repo>/my.tsiptv.json, https://www.example.com/my.tsiptv.json. Share pages and GitHub blob/ links do not work; see hosting an M3U file. You can also skip hosting and use Import from file.
  • HTTPS is recommended; http links work but are not encrypted.
  • Content type: application/json (or text/plain); TS IPTV detects the format by content anyway.
  • Compression: Content-Encoding: gzip is welcome for large files. The 5 MiB limit applies after decompression.
  • Caching: TS IPTV refreshes the root like a playlist (when older than 24 hours, or on Refresh) and each include after its refreshHours. For the file itself and for each include it sends If-None-Match / If-Modified-Since when your server gave an ETag or Last-Modified; answering 304 Not Modified saves bandwidth and counts 0 towards the 50 MiB budget.
  • CORS is not needed by TS IPTV. Add Access-Control-Allow-Origin: * only if web tools should read the file.
  • Keep the link stable. The same id from the same link is an update; from another link, TS IPTV asks whether to replace the existing source.

Add it in TS IPTV

  1. Open Add IPTV Source, paste the link into Source Link and choose Add IPTV, or choose Import from file. TS IPTV recognises the format by its content.
  2. The preview dialog “Add this source?” opens (nothing is stored yet): logo, name, author, description, the numbers of channels, radio, movies and series, “This source contacts these servers” (the hosts of the file and every include), “N items will be skipped” with Details (opens “Import details”) if some entries are invalid, the notice that the source was made by a third party, and the checkbox “I am 18 or older” if the source is marked adult.
  3. Choose Import. TS IPTV loads the includes (“Loading 2 of 4…”). If an include turns out to be adult, it asks again (“Part of this source’s content comes from a source or addon that says it contains adult content.” with “I am 18 or older”); Cancel stores nothing. Then it stores everything, shows for example “Source added: 3 channels, 1 movie, 0 series” (and “N items were skipped” if any) and opens the source's home. On phones, the Home tab has Home (your layout) and Channels (the usual channel list); on TV the rail starts with Home.
  4. Search, Continue watching and favourites work inside the source. About this source (phone: the Source Home menu; TV: a rail item) shows the author; Homepage, which asks “Open … in your browser?” (on a TV without a browser the link is shown as text); each include's status (“Up to date”, “Couldn’t refresh — showing the copy from …”, “Couldn’t load”, or “Held back until 18+ is confirmed” with Confirm); the last refresh with “Problems found in the last refresh: N” and Details (“Problems found”); Refresh and Remove source.
  5. If refreshing the file itself fails, About adds “Last attempt: …”; after a Refresh you start, Home also shows “Couldn’t refresh this source. The saved copy is shown.”. TS IPTV tries again on the normal schedule.

If the file has a document error, TS IPTV shows “Can’t add this source” with the message from the table above and a Details action with the code and path. If every include fails and the file has no items of its own, it shows “None of this source’s content could be loaded. Try again later.”

Common mistakes

MistakeSymptomFix
url and streams on the same itemItem skipped (E_NO_STREAM)Use one: url for a single stream, streams for alternatives.
: in an id (news:hd)Item skipped (E_ITEM_ID; for an include, E_INCLUDE)Use -, _ or .; the colon is reserved for included items.
The same id twice (also across channels, movies, episodes and includes)The second is skipped (E_DUPLICATE_ID)Make every id unique in the file.
rtmp://, rtsp:// or udp:// streamsThe stream is dropped (E_URL); an item whose only stream it was is skipped (E_NO_STREAM)Only http(s) is allowed here. Put such channels in an M3U playlist and add it as an m3u include; whether they play then depends on each platform's player.
A hero with both items and queryitems are used (W_FIELD)Keep one.
groupChips on a movies grid or a rowNo chipsGroup chips work on grids of channels or radio only.
Low-contrast colours (a light background, a dark accent)Your colours are replaced (W_CONTRAST)Use a dark background and an accent with at least 3:1 contrast against it.
A query on an include id that does not exist, or on an xmltv includeSection not shown (W_QUERY_REF)Use the include's exact id; guides cannot be sections.
A misspelt field (nmae)Ignored by the app; the required field is then missingUse the $schema line or the validator; they report unknown fields.
Comments or trailing commas“This file is not valid JSON.”Remove them; use x- fields for notes.
http:// images on hosts that redirect or block themMissing postersUse https image URLs.
An include id starting with epg-Include dropped (E_INCLUDE)That prefix is reserved for epg links.
A stremio include URL without /manifest.jsonInclude dropped (E_INCLUDE)Use the addon's manifest link.
Spaces in a catch-up source (default or append mode)Catch-up dropped, channel plays live (W_FIELD)Encode spaces as %20.
