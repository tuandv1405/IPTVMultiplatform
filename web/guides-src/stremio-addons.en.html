Stremio-compatible addons

An addon is a small web service, or even a folder of static JSON files, that answers a handful of HTTP requests with catalogues, details and stream links. The addon protocol is open and documented; TS IPTV can use any addon that follows it and returns ordinary video links.

TS IPTV includes no channels and no addons. Nothing is pre-installed and TS IPTV does not recommend any addon. Addons are third-party services that you add yourself; you are responsible for having the rights to what you watch through them.

The protocol was created for the Stremio app and is published as the open stremio-addon-sdk specification. TS IPTV is not affiliated with or endorsed by Stremio; “Stremio-compatible” only describes the protocol. Every example uses TS IPTV's own sample addon on tsiptv-8bdd6.web.app, public-domain films from archive.org, a public test stream or example.com placeholders.

What an addon is

An addon is identified by the link to its manifest, a JSON file that always ends in /manifest.json. The manifest says what the addon offers: which content types (movie, series, tv…), which catalogues, and which resources (catalogue lists, details, streams, subtitles). The player then builds further URLs from the manifest's address and requests them with plain HTTP GET. Every answer is JSON. There is no login, no session and no custom transport, which is why an addon can be as simple as a set of files on a static web host.

Addons are useful for publishing your own collection with posters, descriptions, seasons and episodes, for example a home media server, a licensed service you operate, or an archive of public-domain films.

The protocol

The normative text is the SDK's protocol.md and the API reference. This section summarises what an addon author needs.

URLs

The base URL is the manifest link without /manifest.json. All other requests are built from it:

GET {base}/manifest.json
GET {base}/{resource}/{type}/{id}.json
GET {base}/{resource}/{type}/{id}/{extra}.json
ResourcetypeidResponse
catalogthe catalogue's typethe catalogue id from the manifest{ "metas": [ … ] }
metathe item's typethe item id from the catalogue{ "meta": { … } }
streamthe item's typethe video id (a film: its own id; an episode: the episode id; tv: the channel id){ "streams": [ … ] }
subtitlesthe item's typethe video id{ "subtitles": [ … ] }
addon_catalogfrom addonCatalogsfrom addonCatalogs{ "addons": [ … ] }
  • A query string on the manifest link is kept and added after .json of every request. Anything before /manifest.json is kept too; configurable addons put the user's settings there, for example https://addon.example.com/eyJsYW5nIjoiZW4ifQ/manifest.json.
  • SDK servers answer 404 {"err":"not found"} for unknown resources and 500 {"err":"handler error"} when a handler fails; they may also answer with a 307 redirect. Static hosts answer 404 for any file that does not exist.

Encoding: path segments and extra

  • resource, type and id are each encoded like JavaScript's encodeURIComponent: every byte except letters, digits and - _ . ! ~ * ' ( ) becomes %XX. So tt1234567:1:2 is sent as tt1234567%3A1%3A2.
  • extra is name=value pairs joined with &, each name and value encoded the same way: search=his%20girl&skip=100. A space is %20, never +; a literal & or = inside a value becomes %26 or %3D.
  • Extras that allow several values repeat the name: genre=Action&genre=Comedy. TS IPTV writes extras in the order the manifest declares them, with skip last, and leaves out the /{extra} segment when there are none.

A catalogue is { "type", "id", "name", "extra": [ … ] }. The same id may be used for several types. Each extra entry is { "name", "isRequired", "options", "optionsLimit" }:

ExtraMeaning
searchFree-text search. isRequired: true makes a search-only catalogue that is never shown as a row.
genreFilter; the values come from options. A required genre starts on its first option.
skipPaging (below).
other namesAllowed; declare them the same way.

Older manifests use extraSupported/extraRequired string lists and a separate genres list; TS IPTV reads those too, but extra wins when both are present.

Paging

A catalogue page holds up to 100 items. The first page is requested without skip; the following pages with skip=100, skip=200 and so on. The specification says a page with fewer than 100 items is the end. TS IPTV is more lenient: it asks for the next page with skip equal to the number of items received so far and stops at an empty page, a page with no new ids, or an error answer after a short page (a static host's 404). Only declare skip if your catalogue has more than one page.

Catalogue items and details

FieldWhereMeaning
id, type, namebothRequired.
poster, posterShapebothImage; shape poster (portrait, default), square or landscape.
genres, releaseInfo, description, imdbRatingbothText shown on cards and on the detail page.
background, logo, released, runtime, language, country, linksmetaDetail page fields. released is ISO 8601; runtime is text such as "92 min".
videosmetaEpisodes of a series (or a channel's videos). Without videos, the item has one video whose id is the item id.

A video is { "id", "title", "released", "season", "episode", "thumbnail", "overview" }. Season 0 means specials. A released date in the future marks an upcoming episode. If a video carries its own streams array, those are the only streams used for it.

Streams

Each stream object has exactly one source and some labels:

FieldMeaning
urlA direct https (or http) link: MP4, MKV, HLS .m3u8, DASH .mpd.
externalUrlA web page to open in a browser.
nameShort label, for example the quality.
description (older: title)Longer label, may have several lines.
behaviorHints.proxyHeaders.requestHTTP headers to send with every request for this stream, for example { "User-Agent": "…", "Referer": "…" }. The specification requires notWebReady: true alongside.
behaviorHints.notWebReadyThe link cannot play directly in a web browser (not MP4, plain http, or needs headers).
behaviorHints.bingeGroupStreams of the same group are preferred for the next episode.
behaviorHints.filename, videoSizeFile name and size; helps players guess the format.
behaviorHints.countryWhitelistISO 3166-1 alpha-3 codes (lower case) where the stream works.

Other source fields exist in the specification; TS IPTV does not use them (see What TS IPTV plays). Order streams from highest to lowest quality.

Subtitles

GET {base}/subtitles/{type}/{videoId}.json, optionally with videoHash, videoSize and filename in extra, returns { "subtitles": [ { "id", "url", "lang", "label" } ] }. lang is an ISO 639-2 code such as eng; files are SRT or VTT. TS IPTV does not use subtitle addons yet.

Caching

Any response may carry cacheMaxAge, staleRevalidate and staleError (seconds). The SDK turns them into a Cache-Control header and also keeps them in the JSON. TS IPTV honours Cache-Control first, then these fields, then its own defaults (catalogues 1 hour, details 6 hours, streams 5 minutes), and never keeps stream answers longer than 5 minutes.

Types and ids

Types are free strings; movie, series, channel and tv are the common ones. Ids are opaque. Give your ids a prefix of your own (ex_news, tspd_his_girl_friday) and declare it in idPrefixes, so the player only asks your addon about your items. Episode ids are separate ids, for example tspd_superman_s1e1.

Create your own addon

Option 1: static JSON files (no server)

  1. Download the sample files above into a folder with the same tree.
  2. Edit manifest.json: a new id (reverse-DNS of a domain you control), name, description, your own idPrefixes and catalogues.
  3. For each catalogue, write catalog/{type}/{catalogId}.json. Add one file per genre option (catalog/{type}/{catalogId}/genre={option}.json) and, for more than 100 items, …/skip=100.json, …/skip=200.json.
  4. For each item, write meta/{type}/{id}.json; for each film, episode or channel, stream/{type}/{videoId}.json.
  5. Keep ids and extra values URL-safe: letters, digits, _ and -. Validate each file as JSON (VS Code shows errors as you type).
  6. Test locally: in the folder run npx http-server . --cors -c-1 and add http://127.0.0.1:8080/manifest.json (Android emulator: http://10.0.2.2:8080/manifest.json).

Limits of static hosting: no free-text search (queries cannot be pre-generated), one file per genre and page, and no : in ids (the host would look for a file name with :, which Windows and some hosts do not allow).

Option 2: the Node.js SDK

With the official SDK (Node.js 12 or later) you write handlers instead of files, which allows search, large catalogues and computed answers. serveHTTP adds the CORS headers for you and turns the cacheMaxAge, staleRevalidate and staleError values your handlers return into a Cache-Control header.

package.json:

{
  "name": "my-publicdomain-addon",
  "version": "1.0.0",
  "main": "addon.js",
  "scripts": { "start": "node addon.js" },
  "dependencies": { "stremio-addon-sdk": "^1.6.10" }
}

addon.js (the sample addon with search, genre filter and paging):

const { addonBuilder, serveHTTP } = require('stremio-addon-sdk')

const ITEMS = [
  { id: 'tspd_his_girl_friday', type: 'movie', name: 'His Girl Friday',
    releaseInfo: '1940', genres: ['Comedy'],
    poster: 'https://archive.org/services/img/his_girl_friday',
    streams: [{ name: 'archive.org', description: 'MP4 512kb',
      url: 'https://archive.org/download/his_girl_friday/his_girl_friday_512kb.mp4',
      behaviorHints: { filename: 'his_girl_friday_512kb.mp4' } }] },
  { id: 'tspd_superman', type: 'series', name: 'Fleischer Superman (1941-43)',
    releaseInfo: '1941-1943', genres: ['Animation'],
    poster: 'https://archive.org/services/img/superman_the_mechanical_monsters',
    videos: [{ id: 'tspd_superman_s1e1', title: 'The Mechanical Monsters',
      season: 1, episode: 1, released: '1941-11-28T00:00:00.000Z',
      streams: [{ name: 'archive.org', description: 'MP4 512kb',
        url: 'https://archive.org/download/superman_the_mechanical_monsters/superman_the_mechanical_monsters_512kb.mp4' }] }] },
  { id: 'tspd_test_hls', type: 'tv', name: 'HLS Test Channel',
    posterShape: 'square', poster: 'https://archive.org/services/img/his_girl_friday',
    streams: [{ name: 'HLS', description: 'Mux public test stream',
      url: 'https://test-streams.mux.dev/x36xhzz/x36xhzz.m3u8',
      behaviorHints: { notWebReady: true,
        proxyHeaders: { request: { 'User-Agent': 'TSIPTV-Example/1.0' } } } }] }
]
const PAGE = 100

const builder = new addonBuilder({
  id: 'org.example.publicdomain', version: '1.0.0', name: 'My Public Domain Addon',
  description: 'Public-domain films and cartoons, plus a public HLS test channel.',
  resources: ['catalog', 'meta', 'stream'], types: ['movie', 'series', 'tv'],
  idPrefixes: ['tspd_'],
  catalogs: ['movie', 'series', 'tv'].map(type => ({
    type, id: 'tspd-' + type, name: 'Public Domain ' + type,
    extra: [{ name: 'search' }, { name: 'genre', options: ['Animation', 'Comedy'] }, { name: 'skip' }]
  })),
  behaviorHints: { adult: false, p2p: false }
})

const preview = i => ({ id: i.id, type: i.type, name: i.name, poster: i.poster,
  posterShape: i.posterShape, genres: i.genres, releaseInfo: i.releaseInfo })

builder.defineCatalogHandler(({ type, id, extra }) => {
  let list = ITEMS.filter(i => i.type === type && id === 'tspd-' + type)
  if (extra.genre) list = list.filter(i => (i.genres || []).includes(extra.genre))
  if (extra.search) list = list.filter(i => i.name.toLowerCase().includes(extra.search.toLowerCase()))
  const skip = parseInt(extra.skip || '0', 10) || 0
  return Promise.resolve({ metas: list.slice(skip, skip + PAGE).map(preview), cacheMaxAge: 3600 })
})

builder.defineMetaHandler(({ type, id }) => {
  const i = ITEMS.find(x => x.id === id && x.type === type)
  if (!i) return Promise.resolve({ meta: null })
  const meta = preview(i)
  if (i.videos) meta.videos = i.videos.map(({ streams, ...v }) => v)
  return Promise.resolve({ meta, cacheMaxAge: 3600 })
})

builder.defineStreamHandler(({ type, id }) => {
  for (const i of ITEMS) {
    if (i.id === id && i.streams) return Promise.resolve({ streams: i.streams, cacheMaxAge: 600 })
    const v = (i.videos || []).find(v => v.id === id)
    if (v) return Promise.resolve({ streams: v.streams, cacheMaxAge: 600 })
  }
  return Promise.resolve({ streams: [] })
})

serveHTTP(builder.getInterface(), { port: process.env.PORT || 7000 })
  1. Run npm install, then npm start. The SDK prints the manifest link, http://127.0.0.1:7000/manifest.json.
  2. Add that link in TS IPTV on the same computer, or http://10.0.2.2:7000/manifest.json from an Android emulator, or http://<your computer's LAN address>:7000/manifest.json from a phone or TV on the same network.
  3. To publish it, deploy to any Node.js host that gives you an HTTPS address, and use https://<your host>/manifest.json.

The SDK can also generate a configuration page (config in the manifest) and mount the addon in an existing Express app; see the SDK README.

Host it

  • HTTPS. The specification requires HTTPS for everything except 127.0.0.1. TS IPTV also accepts http://, with the warning “This addon does not use an encrypted connection”.
  • CORS. The specification requires Access-Control-Allow-Origin: * on every route, including /manifest.json. TS IPTV is an installed app and does not need it, but web-based players do, so add it.
  • Cache headers. A short Cache-Control: public, max-age=600 on catalogues and details is a good default; keep stream answers short-lived if the links expire.
  • Content type. Serve .json as application/json. No redirect from /file.json to /file.json/.

A GitHub blob/ page or a file-sharing page is not an addon: the manifest link must return the JSON itself.

Add it in TS IPTV

  1. Phone, tablet, iOS and desktop: Profile → Addons → Add addon. Android TV: Settings → Addons → Add addon (type the link with the on-screen keyboard).
  2. Paste the manifest link (it ends with /manifest.json). A stremio://…/manifest.json install link also works; TS IPTV turns it into https://, or http:// for local and LAN hosts (localhost, 127.0.0.1, 10.x, 192.168.x, 172.16–31.x).
  3. Choose Continue. The preview shows the name, version, host, content types, number of catalogues, whether the addon provides streams, and any warning (not encrypted, peer-to-peer, adult content).
  4. Read and accept the notice (“Addons are third-party services, not operated by TS IPTV…”), then choose Add.
  5. Discover appears: on phones between Home and History, on TV at the top of the Home rail. It shows one row per catalogue; open a title and choose a stream to play it.

If the manifest says configurationRequired, TS IPTV does not add it yet: choose Configure to open the addon's /configure page in your browser (on TV the address is shown as text), finish there, and paste the link it gives you. Manage addons (enable, reorder, update, remove) in the same Addons screen. Addon links can contain personal settings, so TS IPTV stores them encrypted and shows only the host.
